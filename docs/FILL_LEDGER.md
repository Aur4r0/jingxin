# 成交同步与历史盈亏

## 本批修改

- 新建独立 `execution_fills` 成交表，不覆盖或删除旧 `trades` 记录。
- 历史交易默认展示交易所真实成交，价格、张数、已实现盈亏和费用来自 OKX fills。
- 成交按模拟环境、API Key 指纹、合约、订单 ID、成交 ID 唯一去重。
- 保存金额原始十进制字符串，用 Decimal 汇总，不用信号价计算或重复乘合约面值。
- 总额覆盖当前 API 配置下的全部已入库成交，不仅是当前一页。
- 将旧订单保留在单独标签，不把默认 filled、估算盈亏或默认 0 手续费当成确认数据。
- 新平仓请求不再写入错误的价差乘张数盈亏，等待成交同步。

## 更新后怎么用

1. 人工暂停所有策略，等待正在执行的任务完成，备份数据库与配套 `.env`。
2. 更新代码并重启或重建应用。首次启动只新增成交表，保留历史订单。切勿在策略仍启用时直接重启。
3. 在历史交易点击同步模拟盘成交。后台每两分钟也会尝试同步一次。
4. 对比 OKX 模拟盘成交明细，核实订单 ID、成交价、张数、手续费及已实现盈亏。
5. 同步或页面刷新不会下单、撤单、平仓或启动策略。页面刷新只读本地数据库。

## 统计口径

- 一行代表一笔成交明细，不代表完整开仓和平仓的一轮交易；一个订单可能有多笔成交。
- 已实现盈亏直接使用 fillPnl。开仓通常返回 0，但开仓成交本身有手续费，因此净交易盈亏可为负。
- 费用原值保留交易所正负号：负数扣费、正数返佣。费用净支出等于扣费减返佣，净交易盈亏等于已实现盈亏加费用原值。
- 缺失数据不能当作 0。存在未知盈亏或非 USDT/未知费用时，不显示完整净盈亏总额。
- 不包含资金费和未平仓浮动盈亏，也不代表账户总收益。

## 当前限制

- 只同步当前已选择的模拟盘，要求完整独立模拟盘凭据，不回退实盘字段。实盘成交同步未开启。
- 默认每次拉取最近七天，最多十页；分页不完整或数据无效时整批回滚，保留既有历史。七天之前未曾入库的成交不会自动补齐。
- 持久化的已同步记录不会因超过七天而被删除。API 历史保留期和网络延迟仍可能造成缺口。
- API Key 指纹用于隔离本地数据，不是交易所账户 UID。同账户换 Key 后需要重新同步，旧 Key 数据保留但不合并到当前总额。
- 无法可靠确定策略归属，因此显示账户级成交，不计算策略排行榜或策略胜率。人工和保护单成交均可能出现在列表中。
- 暂未关联子订单与原开仓组成完整交易，不做开仓费用跨平仓分摊。旧 API `/api/trades` 仍返回旧订单表，不能用作已核实成交接口。
- 本批不修复在线仓位限额、订单幂等恢复及保护单生命周期；这些问题解决前不要恢复无人监督自动交易。

离线回归使用隔离数据库和模拟响应，不调用真实交易账户。部署前务必保留策略暂停状态，实际账户验证仍需操作者完成。

字段含义参照 [OKX API 文档](https://my.okx.com/docs-v5/en/)。
