# 模拟盘对账：先核对，再修复交易流程

当前交付为第一阶段。它不修复在线下单行为，请保持策略暂停。

## VPS 上先做什么

1. 在应用里暂停所有模拟策略，等待执行中的任务结束。
2. 在 OKX 模拟盘核对剩余仓位、止盈和止损单。此工具不会撤单、改单或平仓。
3. 备份数据库和配套 `.env`，再更新代码。不要重新生成 `ENCRYPTION_KEY`。

原生 Python 部署在项目目录执行：

```sh
.venv/bin/python scripts/backup.py
```

Docker 部署在项目目录执行：

```sh
docker compose exec -T jingxin python /opt/app/scripts/backup.py
```

备份目录包含数据库和明文 `.env`，**当前 backup.py 不加密备份包**。目录权限限制不能替代加密；请另行加密保管，不要发到聊天或公开仓库。

## 运行只读对账

原生 Python 部署：

```sh
.venv/bin/python scripts/reconcile_demo.py --inst-id BTC-USDT-SWAP --days 7 --output backups/btc-reconcile.json
```

Docker 部署需先暂停策略、备份，再更新和重新构建容器代码。然后执行：

```sh
docker compose exec -T jingxin python /opt/app/scripts/reconcile_demo.py --inst-id BTC-USDT-SWAP --days 7 --output backups/btc-reconcile.json
```

Docker 报告在宿主机 `data/backups/btc-reconcile.json`；原生部署在 `backups/btc-reconcile.json`。默认自动查询本地已有交易订单 ID，额外订单可加 `--order-id 数字订单ID`。同一路径不能重复写入，第二次请换报告名。

- 只允许模拟盘，必须有独立完整的模拟盘凭据；不回退到实盘字段。
- 仅调用固定 GET 接口，不导入调度器，不写数据库。
- 查询指定合约近 7 天的成交，最多每类 10 页；可调整 `--days` 和 `--max-pages`。
- 返回码 0 表示各读取项目成功；2 表示有读取失败或分页不完整；1 表示工具未完成。0 不代表无风险或可以恢复策略。
- 不会打印底层异常、API 密钥或代理地址。报告仍包含账户订单和成交数据，请勿公开。

## 重点看哪些字段

| 字段 | 含义 |
|---|---|
| warnings | 未暂停策略、保护单数量超过仓位、读取失败等问题 |
| coverage | 每项读取是否成功、分页是否完整；false 时不能认定不存在订单 |
| specification | 面值、最小张数和数量步长，规格无法确认则不计算单位 |
| positions | 当前仓位及张数、基础币数量、USDT 名义金额；保证金单独显示 |
| orders | 交易所订单状态、累计成交张数、成交均价及本地旧记录 |
| fills / fill_totals | 去重成交、窗口内成交均价、已实现盈亏、分币种手续费 |
| fills_without_local_order | 本地没有对应订单的成交，可能来自条件单或人工操作，不自动归属策略 |
| conditional / oco | 当前条件单和 OCO 单，保留算法单 ID、数量、方向和触发价 |

手续费保留 OKX 原始符号，负数扣费、正数返佣。只有盈亏和手续费齐全且费用为 USDT 时，才展示窗口内净交易盈亏。资金费未读取；不能把窗口内净交易盈亏当作账户总盈亏。

快照的各接口读取时间不同，交易所可能在查询期间发生变化。空结果也可能来自历史保留期限制，不能证明历史上没有成交。本地历史记录保持原样，不伪造均价、盈亏或成交状态。

## 后续开发顺序

1. 将集中式合约规格、symbol 归一和剩余额度计算接入开仓前校验；聚合旧仓与未成交开仓单，规格或持仓不明时禁止新开仓。
2. 持久化订单意图、幂等键、账户环境与订单状态；超时保持未知，先查询后处理，禁止盲目重发。
3. 建立独立成交账本，按账户环境、合约和成交 ID 去重；同步条件单成交，未归属成交不强行分配策略。
4. 用实际成交数量建立保护关系，监控单侧失败、触发和残留；异常禁止加仓并持续告警。自动撤改单另行模拟验证。
5. 离线覆盖后，由操作者确认小额模拟盘验证；验证一致再恢复模拟策略。实盘另行确认。

本批新增的合约模块尚未接入在线执行。未实现订单状态机、账本回写、OCO 自动管理、仓位硬上限或故障熔断，不应据此恢复无人监督交易。
