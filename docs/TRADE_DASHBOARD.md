# 历史交易页面重构

## 页面设计

标题和同步状态 → 日期与交易对筛选 → 盈亏核心指标 → 成交计数与费用 → 每日净交易盈亏 → 可折叠成交明细。

- 默认今天，支持昨天、最近7天、最近30天、自定义和全部已同步记录。
- 自定义最多366天，包含结束日；所有自然日按北京时间划分，后端使用 UTC 左闭右开查询。
- 三个核心金额为已实现盈亏、手续费净支出、净交易盈亏；净盈亏突出显示。
- 成交明细默认展开，每页10条，可改20/50条；完整订单号、成交价、张数、费用原值在单行详情中。
- 整体明细可以收起，当前浏览器会记住收起状态。旧订单保持独立入口。
- 使用现有日夜主题和原生日期控件，不新增 UI 框架或第三方运行依赖。

## 数据映射

| 页面字段 | 数据与口径 |
|---|---|
| 日期筛选 | execution_fills.filled_at，UTC 存储，北京时间自然日筛选 |
| 交易对筛选 | execution_fills.symbol，仅当前模拟盘 API 指纹数据 |
| 已实现盈亏 | realized_pnl，即交易所 fillPnl，不重新估算或乘合约面值 |
| 手续费扣款 | USDT 费用原值小于0的绝对值之和 |
| 手续费返佣 | USDT 费用原值大于0之和 |
| 手续费净支出 | 手续费扣款减返佣 |
| 净交易盈亏 | 已实现盈亏加费用原值之和，即减手续费净支出 |
| 成交明细笔数 | 筛选范围内独立成交记录数 |
| 成交订单数 | 筛选范围内订单 ID 去重数 |
| 待核实明细 | 盈亏缺失、费用缺失或费用非 USDT 的明细并集，不重复计数 |
| 每日柱状图 | 同一筛选范围按北京时间自然日分组，不从当前分页计算 |
| 最后成功同步 | 进程内 fills.last_success，失败检查时间不覆盖成功时间；重启后未知 |

空范围显示暂无已入库成交，金额不显示为0。只有存在成交、且对应字段明确返回0时才显示真实零值。缺失字段或非 USDT 费用不按零补齐，完整净额显示待核实，并说明已确认部分。

图表无记录日期以短横线显示，真实零值使用零线标记。全部记录模式仅绘制有成交的日期，避免把历史缺口当作零盈亏。图表支持键盘聚焦和悬停详情，直接使用 DOM/CSS 绘制，不依赖外部图表 CDN。

## 只读统计接口

`GET /api/trades/statistics`

参数：

- `period`：today / yesterday / 7d / 30d / custom / all，默认 today。
- `start_date`、`end_date`：自定义日期，YYYY-MM-DD。
- `symbol`：可选，例如 BTC-USDT-SWAP。

返回 summary、daily、range_label、period、symbol、coverage_warning。金额以十进制字符串返回，缺失值为 null。页面与接口共用同一个查询函数；筛选、图表和翻页不调用交易所。

## 数据范围与安全边界

- 仅统计当前模拟盘 API Key 指纹下已入库的 USDT 永续成交；不与其他账户或旧估算订单合并。
- 同步逻辑仍默认获取最近7天，选择最近30天不会自动补取历史。
- 当前没有持久化的完整同步覆盖记录；最早和最晚成交时间不能证明中间完整无遗漏，因此页面明确提示覆盖有限。
- 不含资金费、充值、提现和浮动盈亏，不等于账户总收益。
- 不计算完整开平仓收益率、策略级排名、胜率或最大回撤，不做跨成交开仓费用分摊。
- 本次不改数据表、不清理记录、不改策略、下单、仓位、保护单、实盘开关或同步执行逻辑。

## 验证

隔离环境使用虚构账户和成交，覆盖日期边界、结束日、跨月与闰日、交易对筛选、分页总额、费用正负号、缺失数据、币种隔离、订单计数、最后成功同步时间与接口/页面一致性。

浏览器预览另行验证日夜主题、桌面与390px手机布局、日期和交易对筛选、分页、每页条数、明细折叠和图表键盘提示。预览禁止策略、交易所连接和写入操作，不代表真实账户验证。

## VPS 更新（已有 Docker 部署）

先在网页人工暂停全部策略，等待正在执行的任务结束，再在项目目录执行：

```sh
docker compose exec -T jingxin python /opt/app/scripts/backup.py
```

确认备份完成后，再依次执行：

```sh
git pull --ff-only
docker compose build
docker compose up -d --no-deps jingxin
docker compose ps
docker compose logs --tail=50 jingxin
```

任何一步失败就先停止，不要强制覆盖。保留 `.env`、`data/` 和原 `ENCRYPTION_KEY`；本批没有新表迁移，不需要初始化或清空数据库。刷新历史交易页面即可使用日期筛选，原记录保留。策略继续保持暂停，交易执行相关风险尚未全部修复。
